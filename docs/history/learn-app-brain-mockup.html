Deep Dive into LLMs like ChatGPT

Andrej Karpathy, 3h31m. My notes in the margin as I watched, the TA’s replies under them, and the two things I wrote down confidently that were wrong. 21 notes so far, 8 concepts touched; the lecture is not finished.

Key concepts

In my own words, from the margin, with the two I had wrong put right.

  • Tokens look like numbers but they are unique ids, symbols for a slice of text. A token can be a word, a slice of a word, whitespace, punctuation. The model never sees characters.
  • Parameters are the weights — knobs on a DJ set, tweaked during training until the predictions come out right. 8B is how many knobs.
  • Inference is the job of predicting the next token: token → network → probabilities → sample → next token. Nothing is learned while it runs.
  • Temperature is how adventurous the sampling is. Low temperature is repeatable, not accurate — the ranking never changes, only how far down the list the coin reaches.
  • A base model is xx parameters trained on yy tokens: Llama 3.1 405B on 15 trillion tokens. It is an internet document simulator, not an assistant.
  • Releasing a model is the code plus the parameters. The tokenizer ships as code with its vocabulary; the training text does not ship.
  • There are two stages, not three. Pre-training is the training; post-training on conversations makes the assistant. Same mechanism, different data.
  • In-context learning is the same thing as the examples in a system prompt: a pattern the model completes inside the window, not an instruction it follows and not something it keeps.
  • Saying “I don’t know” is not a list of unknown facts. It is a learned habit: an internal signal that tends to be present when it is guessing, routed to the refusal words by post-training. It fails in both directions.
  • Tools are trained, not wired: a special token the model learns to emit, an external loop that runs the search and pastes the result back into the context.
  • Knowledge in parameters = vague memory. Knowledge in the tokens of the context window = working memory.

  • 27:05

    Temperature = how much tolerance we have with the probability. low temperature = higher accuracy #til

    Check this

    Low temperature makes the model more repeatable, not more accurate. Temperature reshapes the probability distribution before the coin flip: low makes it peakier, so the top token gets picked almost every time; high makes it flatter, so less likely tokens get real chances. The ranking of tokens never changes. If the top token is wrong, low temperature just gives you that wrong token every time with more confidence. Accuracy comes from the model’s weights and the context, not from the temperature dial.

    TA · What a model release contains

    The release is two files: the Python code describing the network, and the file of parameter values. The tokens you are thinking of, the training text, are not shipped at all. What ships instead is the tokenizer, a small piece of code plus its vocabulary table. That tokenizer knows how to chop any new text into ids and turn ids back into text, exactly the way the model saw text during training. So a new word comes in, the tokenizer maps it to ids, the formula runs with the released numbers, and tokens come out. The knowledge lives in the parameters, not in any stored text.

  • 51:30

    in his notes he says “a lot of the world knowledge” is stored in the parameters of the network - what? how? #doubt

    TA · Knowledge in weights vs knowledge in context

    Nothing is stored and looked up. Your phone keyboard has no list of your sentences in it. It has a pile of numbers that were nudged, over millions of messages, until its guesses got good. Type “I’ll be there in five” and it offers “minutes” not because “minutes” is filed anywhere, but because the numbers came out that way. An LLM is the same trick at scale. Training left the weights shaped so that true-ish continuations are more likely than false ones. Karpathy calls it a lossy compression of the internet, a zip file with a lot lost. So a wrong answer arrives in the same confident voice as a right one, because there is no lookup that could miss. Anything actually in the context window is different: the model can read it directly, like rereading a page. Weights are what it half-remembers; context is what is in front of it.

    Psychology of a base model. in context learning ability? how? — is this similar to the good/bad examples we give in the system prompt? #doubt

    TA · In-context learning and few-shot prompts

    Yes, that is the same idea. In-context learning means the model picks up a pattern from what is in its window and continues it, with no weights changing. Karpathy shows it with ten English-to-Korean word pairs, then a new English word, and the base model completes with the Korean. The examples in a system prompt work the same way: they are not instructions the model follows, they are a pattern the model completes. Same trick, just used to make a base model act like an assistant. Nothing is learned in the training sense; the knobs stay frozen and the pattern only lives inside this one completion.

    pre-training (data gathering and cleaning) -> training (parmeters + transformers etc .. but is there something called as training or everything is pre-training?) -> base model (internet document simulator) -> post training #doubt

    TA · Pretraining vs post-training

    There is no separate stage called training. There are two stages. Pretraining is the training: months of next-token prediction on a huge internet pile, and its output is the base model, like your keyboard tuned on millions of messages. Post-training is a second, much cheaper pass on a small hand-built set of conversations, so the same model learns to answer questions instead of continuing web pages. Same mechanism, different data. So pretraining is not something before training; it is the training.

    we are just creating datasets to tell it when to say no. so how does it know that the next question it doesnt know the answer to is actually not in its training set? is it just a function similar to spaced repitition of types? #doubt

    TA · How a model learns to say “I don’t know”

    It does not know, not directly. It never checks a new question against a list of unknown facts, and it is not spaced repetition. What happens is this: take a fact, generate questions about it, ask the model the same question a few times, and use another LLM as judge to compare its answers to the truth. Where it is consistently wrong, you add training conversations whose correct answer is “I don’t know”. The network already has an internal state that tends to be present when it is guessing, a rough model of its own self-knowledge. Post-training teaches it to route that state to the refusal words. So it is a learned habit, a correlate of uncertainty, which is why it fails in both directions. Keyboard version: it cannot know a word is outside your vocabulary, but it can learn that when its top three suggestions are all weak, offering nothing beats offering junk.

    mitigation 2: allow usage of tools like web search. how do you tell the models to use these tools? again do via training sets #doubt

    TA · Tool use is trained, not wired

    You have it right: it is done via training sets. There is no tool-calling machinery inside the model. Instead, new special tokens are introduced, like a search token, with a format for using them. In post-training, conversations include examples where the assistant emits that token with a query, an external program runs the search, and the results are pasted back into the context window. The model learns from those examples when emitting the token tends to be right. The payoff is that instead of a vague recollection in the weights, the answer becomes text in the context, which the model reads directly, like working memory.
